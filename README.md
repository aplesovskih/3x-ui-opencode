# 3x-ui OpenCode

Скрипт установки панели [3x-ui](https://github.com/MHSanaei/3x-ui) на VPS с выбором и настройкой прокси-сервера.

## Возможности

- Установка панели 3x-ui официальным установщиком;
- **Интерактивный выбор и настройка прокси-сервера**:
  1. `nginx` — reverse proxy;
  2. `caddy` — reverse proxy;
  3. без прокси — панель работает напрямую;
- Автоматическое определение публичного IP и протокола панели (http/https) — прокси настраивается под фактический протокол панели;
- Проверка занятости порта прокси (например, конфликт с xray-inbound на 443) с возможностью указать другой порт;
- При выборе прокси TLS настраивается на самом прокси (если найден сертификат панели в `/root/cert`) — вход по `https://IP:порт` работает корректно;
- В итоговой сводке внешний адрес выводится по домену из сертификата панели (если сертификат выпущен на домен — `https://домен/путь`), иначе — по IP;
- При выборе прокси наружу открывается **только порт прокси**, а порт панели закрывается — доступ к панели возможен исключительно через прокси;
- Настройка firewall (ufw / firewalld) и SELinux (для RHEL-семейства);
- Копия выпущенных сертификатов в `~/cer-backup` на сервере;
- При ошибке выпуска сертификата официальным установщиком (лимит Let's Encrypt и т.п.) предлагается альтернатива: ZeroSSL / self-signed / пропустить;
- Запуск с GitHub одной командой через `curl`.

## Требования

- VPS на ОС: Ubuntu, Debian, CentOS, Rocky Linux, AlmaLinux, Fedora;
- Запуск от `root` (или через `sudo`);
- Открываемый в firewall порт: при выборе прокси — порт прокси (по умолчанию `443`); без прокси — порт панели, который назначит установщик 3x-ui.

## Установка

Запустите команду на сервере:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/aplesovskih/3x-ui-opencode/main/install.sh)
```

Скрипт пошагово:

1. проверит права и зависимости;
2. установит 3x-ui официальным установщиком (следуйте подсказкам установщика);
3. проверит наличие сертификата в `/root/cert` (для домена или IP):
   - сертификат есть — новый не выпускается, существующий просто прописывается в панель;
   - сертификата нет — проанализирует лог установщика: при ошибке выпуска (например, лимит Let's Encrypt) предложит альтернативу — ZeroSSL / self-signed / пропустить;
4. определит публичный IP сервера и реальный порт/путь панели из конфигурации 3x-ui;
5. предложит выбрать прокси-сервер: nginx / caddy / без прокси;
6. настроит reverse proxy под фактический протокол панели, при HTTPS-панели включит TLS на прокси (используя сертификат панели), откроет в firewall только порт прокси и закроет прямой доступ к панели;
7. скопирует выпущенные сертификаты в `~/cer-backup`;
8. выведет итоговую сводку с адресом панели и данными установщика.

> Если панель работает по HTTPS, а прокси без TLS, браузер не сохраняет `Secure`-cookie панели — вход в панель даёт ошибку 403. Поэтому при HTTPS-панели прокси автоматически настраивается с TLS (сертификат берётся из `/root/cert`), и внешний адрес будет `https://IP:порт/путь`. При выборе caddy сертификаты копируются в `/etc/caddy/certs` (caddy работает от пользователя `caddy` и не может читать `/root`).

## Управление

| Команда | Назначение |
|---------|------------|
| `x-ui` | интерактивное меню управления панелью |
| `systemctl status x-ui` | статус службы панели |
| `systemctl restart x-ui` | перезапуск панели |
| `systemctl status nginx` / `systemctl status caddy` | статус прокси |

## Замечания

- Учётные данные панели выдаёт установщик 3x-ui — сохраните их;
- При выборе прокси прямой доступ к панели по её порту закрыт в firewall — панель доступна только через порт прокси;
- Копии выпущенных сертификатов сохраняются в `~/cer-backup` на сервере;
- В итоговой сводке порт в URL опускается, если он стандартный для протокола (443 для `https`, 80 для `http`) — браузер подставит его сам;
- В итоговой сводке адрес панели строится по сертификату: если сертификат в `/root/cert/<домен>` — выводится `https://<домен>/путь`, если сертификат на IP (`/root/cert/ip`) или его нет — `https://<IP>/путь`.
