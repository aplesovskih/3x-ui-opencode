# 3x-ui OpenCode

> # ⚠️ ВНИМАНИЕ
>
> ## Скрипт находится в стадии разработки.
> ### Возможны ошибки и изменения поведения.
> ### Используйте на своё усмотрение и под свою ответственность.

Скрипт установки панели [3x-ui](https://github.com/MHSanaei/3x-ui) на VPS с выбором и настройкой прокси-сервера.

## Возможности

- Установка панели 3x-ui официальным установщиком;
- **Интерактивный выбор и настройка прокси-сервера**:
  1. `nginx` — reverse proxy;
  2. без прокси — панель работает напрямую;
- Автоматическое определение публичного IP и протокола панели (http/https) — прокси настраивается под фактический протокол панели;
- Проверка занятости порта прокси (например, конфликт с xray-inbound на 443) с возможностью указать другой порт;
- При выборе прокси TLS настраивается на самом прокси (если найден сертификат панели в `/root/cert`) — вход по `https://IP:порт` работает корректно;
- В итоговой сводке внешний адрес выводится по домену из сертификата панели (если сертификат выпущен на домен — `https://домен/путь`), иначе — по IP;
- При выборе прокси наружу открывается **только порт прокси**, а порт панели закрывается — доступ к панели возможен исключительно через прокси;
- Настройка firewall (ufw / firewalld) и SELinux (для RHEL-семейства);
- Копия выпущенных сертификатов в `~/cer-backup` на сервере;
- При ошибке выпуска сертификата официальным установщиком (лимит Let's Encrypt и т.п.) предлагается альтернатива: ZeroSSL / self-signed / пропустить;
- Запуск с GitHub одной командой через `curl`;
- Создание Xray-каналов поверх панели скриптом `inbound-xray.sh`: два протокола — VLESS+XHTTP+REALITY и Hysteria2 (WS/gRPC/Trojan/SS и др. скриптом не создаются).

## Требования

- VPS на ОС: Ubuntu, Debian, CentOS, Rocky Linux, AlmaLinux, Fedora;
- Запуск от `root` (или через `sudo`);
- Открываемый в firewall порт: при выборе прокси — порт прокси (по умолчанию `443`); без прокси — порт панели, который назначит установщик 3x-ui.

## Установка

Запустите команду на сервере:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/aplesovskih/3x-ui-opencode/main/install.sh)
```

Скрипт пошагово:

1. проверит права и зависимости;
2. установит 3x-ui официальным установщиком (следуйте подсказкам установщика);
3. проверит наличие сертификата в `/root/cert` (для домена или IP):
   - сертификат есть — новый не выпускается, существующий просто прописывается в панель;
   - сертификата нет — проанализирует лог установщика: при ошибке выпуска (например, лимит Let's Encrypt) предложит альтернативу — ZeroSSL / self-signed / пропустить;
4. определит публичный IP сервера и реальный порт/путь панели из конфигурации 3x-ui;
5. предложит выбрать прокси-сервер: nginx / без прокси;
6. настроит reverse proxy под фактический протокол панели, при HTTPS-панели включит TLS на прокси (используя сертификат панели), откроет в firewall только порт прокси и закроет прямой доступ к панели;
7. скопирует выпущенные сертификаты в `~/cer-backup`;
8. выведет итоговую сводку с адресом панели и данными установщика.

> Если панель работает по HTTPS, а прокси без TLS, браузер не сохраняет `Secure`-cookie панели — вход в панель даёт ошибку 403. Поэтому при HTTPS-панели прокси автоматически настраивается с TLS (сертификат берётся из `/root/cert`), и внешний адрес будет `https://IP:порт/путь`.

## Управление

| Команда | Назначение |
|---------|------------|
| `x-ui` | интерактивное меню управления панелью |
| `systemctl status x-ui` | статус службы панели |
| `systemctl restart x-ui` | перезапуск панели |
| `systemctl status nginx` | статус прокси |

## Настройка Xray-каналов (inbound-xray.sh)

Дополнительный скрипт для создания каналов (inbound) поверх уже установленной панели:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/aplesovskih/3x-ui-opencode/main/inbound-xray.sh)
```

> Запуск от `root` (скрипт пишет в базу панели `/etc/x-ui/x-ui.db` и перезапускает `x-ui`). Если вошли под обычным пользователем — сначала `su -`; `sudo` внутри команды не используется. Отсутствующие зависимости (sqlite3, openssl, curl) скрипт предложит установить.

- **⚠️ Важно: поддержка панели 3x-ui v3.6+ (формат базы данных).** На более старых версиях панели схема таблиц отличается — скрипт не работает. Скрипт работает только с SQLite-базой (XUI_DB_TYPE=postgres не поддерживается).
- Скрипт работает как главное меню: создание канала, включение/отключение заглушки, включение подписки.
- Создаёт канал напрямую в базе панели (`sqlite3`, `/etc/x-ui/x-ui.db`) с последующим перезапуском `x-ui` — без REST API.
- Меню из двух протоколов: VLESS+XHTTP+REALITY (TCP, mode=stream-one) и Hysteria2 (UDP/TLS).
- Порт запрашивается интерактивно; при пустом вводе — автоподбор свободного.
- Для каждого канала создаётся клиент (vless/hy2) и генерируется share-ссылка: `vless://` или `hysteria2://`.
- Требования к клиенту: поддержка XHTTP `mode=stream-one` и совпадение версии Xray-ядра клиента с панелью (иначе трафик XHTTP не идёт).
- Опциональная интеграция с nginx (с бэкапом конфигурации и откатом при `nginx -t`): в режиме stream-мастера все внешние TLS-потоки идут на единый 443, маршрутизация по SNI (`stream_ssl_preread`); xhttp+reality-канал за мастером получает строку в SNI-map, hysteria работает по прямому UDP-порту.
- **Заглушка (landing):** панель скрывается на своём пути (`/panel` по умолчанию), а на корневом адресе — нейтральная заглушка-сайт. Включение/отключение из меню; после включения выводятся логин/пароль/адрес панели.
- **Подписка пользователя:** включается из меню (пункт 4) — URL вида `https://адрес/sub/<subId>`. Настраиваются `subURI`/`subDomain`/`subEnable` в базе панели, nginx-локация `/sub/`, а для каналов за прокси пишутся записи в таблицу `hosts` (внешний адрес/порт/SNI/path — ссылки в подписке корректные). Ссылка на подписку выводится в сводке каждого канала.
- Прямые порты каналов открываются в firewall (Hysteria2 — UDP); за stream-мастером каналы наружу не открываются (доступен только 443).
- TLS для каналов берётся из сертификата панели (`/root/cert`); если его нет — выпускается self-signed (в `/etc/ssl/x-ui-inbound/`).
- Переменные окружения: `XUI_DB` (путь к базе), `XUI_XRAY` (путь к бинарнику xray), `XUI_LOG` (путь к логу, по умолчанию /var/log/setup-xray.log).
- Лог операций: `/var/log/setup-xray.log`.

## Замечания

- Учётные данные панели выдаёт установщик 3x-ui — сохраните их;
- При выборе прокси прямой доступ к панели по её порту закрыт в firewall — панель доступна только через порт прокси;
- Копии выпущенных сертификатов сохраняются в `~/cer-backup` на сервере;
- В итоговой сводке порт в URL опускается, если он стандартный для протокола (443 для `https`, 80 для `http`) — браузер подставит его сам;
- В итоговой сводке адрес панели строится по сертификату: если сертификат в `/root/cert/<домен>` — выводится `https://<домен>/путь`, если сертификат на IP (`/root/cert/ip`) или его нет — `https://<IP>/путь`.
